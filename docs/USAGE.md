# MARIS usage guide / 使用规范

## 0. Basic requirements

An Agent Skills-compatible host with access to your authorized task artifact. No persistent profile or account needed. Python 3.10+ is needed only for opt-in local history handling.

### Flow (in-session collaboration, opt-in)

Ask: `Use MARIS in flow mode while completing this task. Keep routine steps autonomous, pause only at a material design, safety or scientific assumption checkpoint.`

Only the **active host agent** can follow this protocol. It does not attach to a separate running agent or read its private internal reasoning. Modes: `quiet` critical only, `balanced` important decisions (default), `learning` optional short explanations. Never self-approve an irreversible action requiring human approval.

### Review, the default mode

Ask: `Use MARIS to review this code diff. Focus on decisions I need to understand or verify before acceptance. Read only the task-related files and don't modify anything.`

Expected output: mission, profile on/off disclosure, evidence coverage, at most 3 decision cards, low-attention section, Explain/Verify/Challenge choices.

MARIS must not execute tests, upload artifacts, rewrite files or merge PRs without distinct user authorization.

### Explain

Ask: `Explain decision #1 from the MARIS brief; I know Python but not numerical stability.`

Output: concise causal explanation for *the actual task*, not an encyclopedic tutorial. May offer an optional one-question teach-back check; no implicit mastery score.

### Verify

Ask: `Verify decision #2. First tell me which tests you plan to run.`

MARIS suggests a minimal check. Running potentially side-effectful commands or changing files requires user permission and host-enforced tool permissions.

### Challenge

Ask: `Challenge decision #1: give me a counterexample or assumption under which this recommendation fails.`

Output: alternative explanations and evidence gaps clearly labeled, no invented proof.

### Profile (optional)

1. User provides chosen sources, not a blanket "all history" search.
2. Agent explains source scope, title exposure, excerpt/model processing and the purpose before any read.
3. After user consents to source access, helper `catalog` lists available conversation titles and user-message counts.
4. User chooses specific indices (maximum 8 at a time), agent asks permission to stage and to let the host/model read selected text. These are distinct permissions.
5. `stage ... --indices ... --consent` writes `.maris/private/staged.json` locally with bounded user excerpts; nothing is auto-uploaded by the helper.
6. Agent proposes a minimally scoped profile and shows each field, basis and effect on review. User reviews/edit the candidate file generated by `template`.
7. `approve --confirm APPROVE-MARIS-PROFILE` only after the user says yes to the exact candidate. The helper saves only approved structured fields; no raw transcripts.
8. At review time, `Profile: on` identifies approved reuse. User can say `Without my profile` or revoke approval and erase local profile files.

**Important:** Stage files contain private excerpts. The host agent's chosen model can receive those excerpts when reading them. The local script never connects to the Internet, but that does not mean the end-to-end process is offline.

## Supported import shapes

- ChatGPT `conversations.json` (the official data export), or `.zip` containing a conversations JSON entry (only the JSON entry is read; files are not extracted).
- Curated `.md` / `.txt` local conversation, interpreted as one catalog item.
- A minimal JSON array of objects with `title` and `messages: [{role:'user', content:'...'}]`, for demo and testing.

Only **user** message text is staged from supported JSON. The user must choose which conversations to include. Selected text is truncated for minimized exposure, so the profile must be treated as incomplete and corrigible.

## Commands from a project working directory

```bash
python /path/to/skills/maris/scripts/profile.py catalog --input /path/to/conversations.json
python /path/to/skills/maris/scripts/profile.py stage --input /path/to/conversations.json --indices 2,5 --consent
python /path/to/skills/maris/scripts/profile.py template
# After reviewing/editing the candidate JSON:
python /path/to/skills/maris/scripts/profile.py approve --confirm APPROVE-MARIS-PROFILE
python /path/to/skills/maris/scripts/profile.py show
python /path/to/skills/maris/scripts/profile.py erase --confirm DELETE-MARIS-LOCAL-DATA
```

Use `--replace` only when intentionally overwriting an existing staged file, candidate or approved profile. MARIS should ask for confirmation first.

## Cannot do

- Read hidden ChatGPT/cloud histories without user-selected exports or a separately authorized host connection.
- Infer proven skill mastery from the frequency of topic mentions.
- Promise data never goes to the hosting agent's configured model provider.
- Carry a profile across workspaces automatically, continuously monitor the agent, guarantee safety/correctness, or provide a certified code audit.
- Reuse cognitive profile data for social, dating, psychological or marketing purposes.
